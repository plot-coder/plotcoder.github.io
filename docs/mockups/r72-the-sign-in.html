R72: a sign-in for the door

Drawn 2026-09-21 on Robert's "let's build a sign in for users", from round twenty-two's C1: the desktop app's connector screen says OAuth is "Detected" on a door that has none, and the way through is "No sign-in" and a password base64 in a header. What follows is the one page a person would see, beside what ships today, and the question.

1 · What the writer does at the connector screen

As it ships. Add custom connector: name, the address, then Authentication: the screen says OAuth is "Detected" and preselects "Sign in now". The writer must choose "No sign-in" instead and type a header — authorization, Basic dGVzdEB0ZXN0LmNvbTp0ZXN0 — which is their email and password, base64, sitting in a settings screen. The on-ramp, the door's root and the prompt each explain this.
With R72. Add custom connector: name, the address. The screen says Sign in, because the door now says where its sign-in is. The writer presses it; a browser tab opens on plotcoder.com; they see page 2 below; they press Allow; the tab closes and the tools are there. Nothing else to type. The header still works for anyone with a script, and for the test account.

2 · The page on plotcoder.com, two ways it can be met

Signed in already · one question

plotcoder.com/oauth/consent

Let Claude work your walls?

You are signed in as mairead@example.com.

Claude is asking to work your PlotCoder account as you: every project you are on, reading and writing, until you take it back.

Not you? Sign out on plotcoder.com first. You can take this back any time from the account sheet.

The writer's own session on plotcoder.com carries over: same origin, same sign-in. The app's words for who the asker is come from what the connector registered itself as — the desktop app says "Claude"; a script would say its own name. One question, two answers, and back.

Signed out · the app's sign-in, then the question

plotcoder.com/oauth/consent

Sign in to let Claude work your walls

Claude is asking to work a PlotCoder account. Sign in as yourself first.

Your email and a password, as on the app. No account yet? Claim one on plotcoder.com, then come back.

The same form the account sheet has, the password hashed on the device before it is sent (R39), and then the page on the left. Not a second sign-in system: the app's own, on a page of its own.

3 · What the door says, for a client

GET https://mcp.plotcoder.com/.well-known/oauth-protected-resource
{ "resource": "https://mcp.plotcoder.com",
  "authorization_servers": ["https://kmpahjsggbleygsnuwug.supabase.co/auth/v1"],
  "bearer_methods_supported": ["header"] }

POST https://mcp.plotcoder.com            (no sign-in)
HTTP/1.1 401
WWW-Authenticate: Bearer resource_metadata="https://mcp.plotcoder.com/.well-known/oauth-protected-resource"

POST https://mcp.plotcoder.com
Authorization: Bearer eyJ…                 (a token the writer allowed, from the project's own auth)
→ the same server, as that writer, session id and all

POST https://mcp.plotcoder.com
Authorization: Basic base64(email:password) (as today; scripts, the CLI, the test account)

The authorization server is PlotCoder's own Supabase Auth, switched on as an OAuth 2.1 server on the dashboard; the desktop app registers itself with it (dynamic client registration), so there is no client id to hand anyone. The door takes a bearer token only if the project's keys sign it and it was minted for a connector, never the app's own session token.

The question

Is this the best we can do? The alternatives: keep the header (nothing to build, and every writer keeps a password in a settings screen under a prompt that misreads the door); make the door its own authorization server, minting tokens in the function (a second sign-in beside the account's, with keys to keep); take Supabase's ready-made consent screen (it is a page of ours anyway, and the words should be the app's). I recommend the pages above: the account the writer already has, one new page, the header kept for scripts.

What Robert decides:
  • the words on page 2 — "work your walls", "as you", "until you take it back";
  • whether the header stays as a second way in (I say yes: the CLI, scripts and the test account use it);
  • the dashboard switches are his hand: Authentication › OAuth Server on, dynamic client registration on, authorization path /oauth/consent, site URL https://plotcoder.com.
